Microservices Architecture Guide

1. Architecture Overview

Transitioning from a MERN monolith to an event-driven, containerized microservices architecture. This design ensures scalability, fault isolation, and independent deployability.

Core Principles

  • ✓ Database per Service: Product (MongoDB), Order/Auth (PostgreSQL).
  • ✓ Event-Driven: Kafka for async communication (e.g., Order Created → Notification).
  • ✓ API Gateway: Single entry point for routing, rate limiting, and auth validation.
  • ✓ Observability: Centralized logging (Loki) and metrics (Prometheus/Grafana).

Tech Stack

Node.js / Express MongoDB PostgreSQL Apache Kafka Docker / Compose Prometheus / Grafana

5. Shared Libraries

Critical utilities that every service imports to ensure consistent logging, error handling, and Kafka communication.

shared/src/logger.js

const winston = require('winston');
const { format } = winston;

// Define log format: Timestamp, Level, Service Name, Message, and optional metadata
const logFormat = format.combine(
  format.timestamp({ format: 'YYYY-MM-DD HH:mm:ss' }),
  format.errors({ stack: true }),
  format.printf(({ level, message, timestamp, stack, service, ...meta }) => {
    return JSON.stringify({
      timestamp,
      level,
      service: service || 'unknown-service',
      message,
      ...(stack && { stack }),
      ...(Object.keys(meta).length && { meta })
    });
  })
);

const logger = winston.createLogger({
  level: process.env.LOG_LEVEL || 'info',
  format: logFormat,
  defaultMeta: { service: process.env.SERVICE_NAME },
  transports: [
    new winston.transports.Console(),
    // In production, add Loki or File transport here
    // new winston.transports.File({ filename: 'combined.log' })
  ]
});

module.exports = logger;

shared/src/errorHandler.js

const logger = require('./logger');

class AppError extends Error {
  constructor(message, statusCode) {
    super(message);
    this.statusCode = statusCode;
    this.status = `${statusCode}`.startsWith('4') ? 'fail' : 'error';
    this.isOperational = true;
    Error.captureStackTrace(this, this.constructor);
  }
}

const globalErrorHandler = (err, req, res, next) => {
  err.statusCode = err.statusCode || 500;
  err.status = err.status || 'error';

  logger.error('Error occurred', {
    error: err.message,
    stack: err.stack,
    path: req.path,
    method: req.method
  });

  if (process.env.NODE_ENV === 'development') {
    res.status(err.statusCode).json({
      status: err.status,
      error: err,
      message: err.message,
      stack: err.stack
    });
  } else {
    // Production: Do not leak stack traces
    if (err.isOperational) {
      res.status(err.statusCode).json({
        status: err.status,
        message: err.message
      });
    } else {
      logger.error('Programming error or unknown error', { error: err });
      res.status(500).json({
        status: 'error',
        message: 'Something went very wrong!'
      });
    }
  }
};

module.exports = { AppError, globalErrorHandler };

6. Core Services Implementation

services/api-gateway/index.js

const express = require('express');
const { createProxyMiddleware } = require('http-proxy-middleware');
const rateLimit = require('express-rate-limit');
const logger = require('../../shared/src/logger');

const app = express();
const PORT = process.env.PORT || 8080;

// Rate Limiting
const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 100, // limit each IP to 100 requests per windowMs
  message: 'Too many requests from this IP, please try again later.'
});
app.use(limiter);

// Request Logging Middleware
app.use((req, res, next) => {
  logger.info('Incoming request', { method: req.method, path: req.path, ip: req.ip });
  next();
});

// Routing to Microservices
app.use('/api/auth', createProxyMiddleware({
  target: process.env.AUTH_SERVICE_URL || 'http://localhost:4001',
  changeOrigin: true,
  pathRewrite: { '^/api/auth': '' }
}));

app.use('/api/products', createProxyMiddleware({
  target: process.env.PRODUCT_SERVICE_URL || 'http://localhost:4002',
  changeOrigin: true,
  pathRewrite: { '^/api/products': '' }
}));

app.use('/api/orders', createProxyMiddleware({
  target: process.env.ORDER_SERVICE_URL || 'http://localhost:4003',
  changeOrigin: true,
  pathRewrite: { '^/api/orders': '' }
}));

// Health Check
app.get('/health', (req, res) => {
  res.status(200).json({ status: 'UP', service: 'api-gateway' });
});

app.listen(PORT, () => {
  logger.info(`API Gateway running on port ${PORT}`);
});

services/order-service/kafkaProducer.js (Event Emission)

const { Kafka } = require('kafkajs');
const logger = require('../../shared/src/logger');

const kafka = new Kafka({
  clientId: 'order-service',
  brokers: [process.env.KAFKA_BROKER || 'localhost:29092']
});

const producer = kafka.producer();

const connectProducer = async () => {
  try {
    await producer.connect();
    logger.info('Kafka Producer connected successfully');
  } catch (error) {
    logger.error('Failed to connect Kafka Producer', { error });
  }
};

const publishOrderEvent = async (orderData) => {
  try {
    await producer.send({
      topic: 'order-created',
      messages: [
        { value: JSON.stringify(orderData) }
      ]
    });
    logger.info('Order event published to Kafka', { orderId: orderData.id });
  } catch (error) {
    logger.error('Failed to publish order event', { error, orderData });
    // Implement retry logic or dead-letter queue here
  }
};

module.exports = { connectProducer, publishOrderEvent };

8. Step-by-Step Execution Guide

Follow these exact steps to bootstrap and run the entire architecture locally.

Step 1: Initialize Project

Create the root directory and copy the structure.

mkdir techhub-microservices && cd techhub-microservices
# Create folders based on the structure provided in Tab 3
mkdir -p infrastructure/{prometheus,grafana/provisioning,loki,kafka}
mkdir -p shared/src/{kafka,middleware}
mkdir -p services/{api-gateway,auth-service,product-service,order-service,notification-service}
mkdir scripts

Step 2: Setup Shared Dependencies

Initialize the shared library that all services will link to.

cd shared
npm init -y
npm install winston kafkajs express
# Create the logger.js and errorHandler.js files from Tab 5
cd ..

Step 3: Configure Environment

Create the master `.env` file at the root.

NODE_ENV=development
SERVICE_NAME=techhub-platform

# Database
MONGO_URI=mongodb://root:rootpassword@mongodb:27017/techhub?authSource=admin
POSTGRES_URI=postgresql://techhub:techhubpassword@postgres:5432/techhub_db

# Kafka
KAFKA_BROKER=kafka:9092

# Services
AUTH_SERVICE_URL=http://auth-service:4001
PRODUCT_SERVICE_URL=http://product-service:4002
ORDER_SERVICE_URL=http://order-service:4003

Step 4: Spin Up Infrastructure

Start databases, Kafka, and monitoring tools. This runs in the background.

# Start only infrastructure services (defined in docker-compose.yml)
docker-compose up -d mongodb postgres redis zookeeper kafka prometheus grafana loki

# Verify they are running
docker ps

Step 5: Develop & Run Services

For each service (e.g., api-gateway), initialize and run:

cd services/api-gateway
npm init -y
npm install express http-proxy-middleware express-rate-limit dotenv
npm link ../../shared  # Link shared logger/utils

# Create index.js (from Tab 6) and Dockerfile
docker-compose up --build api-gateway

Step 6: Verify & Monitor

Test the gateway and check logs.

# Test Gateway Health
curl http://localhost:8080/health

# View aggregated logs in Grafana (Loki data source)
# Or view docker logs directly:
docker-compose logs -f api-gateway order-service
